# JavaFX 麻将游戏接口骨架

当前工程包含可编译的 MVC 接口骨架，以及“创建/加入好友房 → 等待入房 → 好友牌局 → 单局结算 → 下一轮/累计排名”的 JavaFX 可交互 Demo。

- 接口源码：`src/main/java/com/campus/mahjong/api/`
- 结构说明：`docs/INTERFACE_DESIGN.md`
- MVC 包结构：`docs/MVC_PACKAGE_STRUCTURE.md`
- 分阶段实现计划：`docs/IMPLEMENTATION_ROADMAP.md`
- 地区规则口径：`docs/REGIONAL_RULES.md`
- SQLite 数据设计：`docs/SQLITE_SCHEMA.md`
- 编译验证：`mvn compile`
- 启动主页面：`mvn javafx:run`

## 当前已完成

- 明亮轻快的统一页面主题与响应式卡片布局
- 创建/加入房间、玩法与倍率/轮次/封顶配置
- 等待房间、玩家席位、准备状态和开局校验
- 动态手牌、选牌、出牌、摸牌及牌桌弃牌区
- 单局结算、本房累计积分、好友长期积分榜和多轮推进
- 136 张牌墙、权威回合状态机、吃碰杠胡校验、胡牌/流局结算
- revision 乐观锁、基础牌型分析、倍率与封顶计分
- 房主内置 TCP 临时服务器、热点内多机加入与房间快照广播
- 四客户端准备/开局、玩家私有手牌快照与第一局实时操作同步

`DemoSession` 仍保留为本地演示回退；从首页创建或加入房间时使用 TCP 服务端权威快照。

玩家档案、对局记录与累计积分已写入 `data/mahjong.db`；该数据库文件不会提交到 Git。

## 热点联机试运行

1. 房主电脑开启 Wi-Fi 热点，四台电脑都连接到该热点。
2. 四台电脑分别运行 `mvn javafx:run`。
3. 房主点击“创建好友房”，首次启动监听时允许 Java 通过系统防火墙。
4. 房主在等待页复制 `房主IP:19090#房间码` 格式的完整邀请地址。
5. 另外三名玩家在首页粘贴完整邀请地址并加入、准备。
6. 四人全部在线且准备后，房主点击开始；四端会进入同一个服务端权威牌局。

服务端默认监听 TCP `19090`。如果自动识别到的不是热点网卡地址，可以通过 JVM 参数显式指定：

```bash
mvn -Dmahjong.hostAddress=192.168.137.1 javafx:run
```

当前所有玩法采用血战到底的轮次流程：胡牌者退出本轮操作，其余玩家继续；三家胡牌或牌墙耗尽后，服务端自动发下一轮。全部设定轮次结束后，四端进入总排名与逐笔流水页面。已胡玩家不再承担后续自摸付款；点炮倍率和封顶延续原规则，同一弃牌允许多家胡牌。

流水包含轮次、付款方、收款方、胡牌方式、牌型和积分，结算页将每轮积分及流水幂等保存到本机 SQLite。当前未另加杠牌计分、查叫或退税规则。

联机协议已更新至版本 3，参与同一房间的客户端应使用同一新版。断线令牌恢复、碰杠胡响应的超时托管仍未实现；任一尚未胡牌的玩家在响应窗口掉线时，本局可能需要重新创建房间。

## 四川麻将定缺

发牌后、庄家首次出牌前，四家各自选择万、筒、条中的一个缺门。本轮选定后不能修改；选择期间仅公开各家是否完成，全部完成后公开缺门并开始出牌。

定缺倒计时为 10 秒，由房主服务器统一推进；四家提前选完立即开始。超时者自动选择手牌（含庄家摸牌）中数量最少的花色，同数按万、筒、条顺序选择。其他玩法不进入定缺阶段，每个新四川轮次重新定缺。

持有缺门牌时必须优先打出缺门牌，后续摸到缺门牌同样适用；不能碰、明杠、暗杠、补杠缺门牌，也不能带缺门牌胡牌。客户端禁用不合法出牌，服务端再次校验。

规则依据：[游戏茶苑四川麻将定缺说明](https://www.gametea.com/ask/201809/7375.html)。10 秒时长与超时选择策略为本项目约定。

每次进入出牌阶段开始 15 秒倒计时，房主服务器统一判断超时并广播自动出牌结果。有缺门牌时优先打缺门；否则打本次摸到的牌。碰牌后没有摸牌时，从合法手牌中选择一张。碰杠胡响应阶段不使用出牌倒计时。定缺后手牌按缺门在最右侧排列，后续摸牌和整理同样保持这一顺序。
