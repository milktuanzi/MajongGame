# 成员2：JavaFX UI、交互与视觉设计负责人

## 任务定位

负责所有客户端页面、交互状态和明亮轻快的视觉体系。页面只消费 ViewModel 和服务接口，不包含麻将规则判断、Socket 通信或数据库代码。

## 负责页面

1. 好友房首页：昵称、玩法、轮次、倍率、封顶配置，创建房间或输入6位房间码加入。
2. 等待入房页：房间码、复制邀请、四个座位、连接状态、准备状态、房主开始按钮。
3. 牌局页：四方玩家、牌墙、弃牌区、本人手牌、吃碰杠胡/过、倒计时和网络状态。
4. 单局结算页：胡牌类型、计分项、分数变化、房间内排名和下一轮按钮。
5. 房间总结算页：全部轮次统计、好友累计积分变化、返回首页与再开一局。
6. 好友积分榜：累计积分、胜局、对局数、胜率和最近共同对局。
7. 通用弹窗：退出确认、断线重连、操作超时、房间不存在、版本不兼容。

## UI 设计规范

- 继续使用暖白、浅薄荷绿、珊瑚红和柔和金色，保证整体明亮轻快。
- FXML 只负责结构，CSS 负责颜色、字体、圆角、阴影和控件状态。
- 所有主要操作按钮提供默认、悬停、按下、禁用和等待状态。
- 等待页和牌局页必须明显区分“已连接、已准备、掉线、正在重连”。
- 牌局中自己的暗牌可见，其他玩家只能显示牌背和公开牌。
- 最小适配分辨率为 `1024×680`，推荐分辨率为 `1280×760`。
- 禁止用颜色作为唯一状态提示，同时配合文字或图形标识。

## 交互状态要求

- 创建/加入房间期间禁用重复提交，并显示加载状态。
- 房间码必须限制为6位数字，错误提示显示在输入框附近。
- 非房主不能修改房间配置或开始游戏。
- 玩家未全部进入、未全部准备时，房主开始按钮保持禁用。
- 未轮到本人时禁用出牌；只显示规则引擎返回的合法动作。
- 网络中断时覆盖牌桌操作层，重连成功后使用完整快照刷新页面。
- 结算页同时展示“本局变化”和“好友累计排名”，避免混淆。

## 接口协作

- 从成员1获得 `NavigationService`、`SessionContext` 和各页面 ViewModel。
- 通过成员3的房间事件显示连接/准备状态，不直接解析网络报文。
- 通过成员4的 `GameSnapshot`、`ActionOption` 和 `Settlement` 渲染牌局。
- 通过成员5的 `FriendScoreService` 展示好友排名和历史统计。

## 阶段安排

1. 第1周：完成页面线框图、颜色字体规范和公共控件规范。
2. 第2周：完成首页、创建/加入房间与表单校验。
3. 第3周：完成等待入房页、玩家座位卡和断线状态。
4. 第4周：完成牌桌、手牌、公开牌、操作按钮和倒计时。
5. 第5周：完成单局/总结算、好友积分榜和通用弹窗。
6. 第6周：完成多分辨率测试、动效优化和联调缺陷修复。

## 交付物

- 全部 FXML、CSS、图片资源和 JavaFX Controller/ViewModel。
- UI 状态清单与页面跳转说明。
- 关键页面截图和操作演示录像。
- 可复用的玩家卡片、麻将牌、状态徽标、提示条组件。

## 验收标准

- 所有页面可以通过键盘和鼠标完成主要操作。
- 1024×680 下无文字遮挡、控件重叠或重要内容越界。
- 页面不阻塞 JavaFX Application Thread。
- 房间和牌局状态变化能实时反映，旧页面取消事件订阅。
- UI 不自行判定“能否胡牌”或计算积分。
