# 成员4：麻将规则、牌局状态机与结算负责人

## 任务定位

负责完整麻将领域逻辑，保证发牌、轮转、合法动作、胜负判断和计分可重复、可测试。规则层必须是纯 Java，不依赖 JavaFX、Socket 或数据库。

## 功能任务

- 建立牌、牌墙、手牌、弃牌、公开组合、座位、庄家和轮次领域模型。
- 使用可注入随机种子完成洗牌和发牌，便于复现测试失败。
- 实现牌局状态机：准备、发牌、摸牌、等待出牌、响应、结算、下一轮、结束。
- 实现出牌、碰、杠、胡、过及超时托管动作。
- 实现一炮多响、自摸、流局、杠后开花等公共流程，差异由具体规则实现决定。
- 实现四川、红中麻将的规则策略与计分项。
- 生成按玩家视角过滤的 `GameSnapshot`，隐藏其他玩家暗牌。
- 生成 `Settlement` 和 `ScoreChange`，保证分数变化总和符合房间规则。

## 关键接口

- 实现 `MahjongRuleEngine`：`initialize`、`legalActions`、`apply`、`isRoundFinished`、`settle`。
- 实现 `RuleEngineRegistry`，按 `ModeCode` 返回对应规则。
- 实现 `GameSessionService`，为网络层提供快照、动作和结算用例。
- 通过 `GameEventBus` 发布牌局状态变化和结算事件。

## 状态机约束

```text
PREPARING → DEALING → PLAYING → SETTLING
                         ↑          │
                         └─下一轮───┘
                                    ↓
                                 FINISHED
```

- 任何动作都必须验证当前状态、行动者、牌的所有权和 `expectedRevision`。
- 响应窗口内先收集所有玩家操作，再按“胡 > 杠 > 碰 > 过”的规则优先级处理。
- 规则实现不能直接修改数据库；结算结果交由成员5持久化。
- 规则引擎不得读取网络会话对象或 JavaFX 控件。

## 规则完成顺序

1. 先实现通用牌模型、回合状态机和红中麻将，作为最小可玩版本。
2. 完成公共碰杠胡、流局和基础结算。
3. 实现四川麻将差异规则与计分。
4. 完善红中赖子替代与四红中计分。
5. 完善四川及红中血战流程与边界测试。
6. 使用统一规则测试套件验证四种实现。

## 阶段安排

1. 第1周：领域建模、状态图、牌编码规范和规则差异表。
2. 第2周：洗牌、发牌、摸打、轮转和基础合法性校验。
3. 第3周：碰杠胡、响应优先级和红中麻将最小可玩版本。
4. 第4周：四川与红中规则实现。
5. 第5周：结算、轮次推进、总结算和玩家视角快照。
6. 第6周：规则边界测试、联机联调和缺陷修复。

## 测试要求

- 每类牌型至少包含成功、失败和边界测试。
- 洗牌测试使用固定随机种子，禁止依赖偶然结果。
- 测试重复出牌、非本人回合、非法碰杠、重复响应和旧版本操作。
- 测试流局、最后一张牌、空牌墙、断线托管及多轮结束。
- 每种地方规则使用同一批公共行为测试，再增加其专属规则测试。

## 交付物

- 四种玩法规则实现和规则注册器。
- 完整牌局状态机与玩家视角快照转换。
- 单局结算、轮次累计和房间总结算结果。
- 规则差异文档及自动化测试集。

## 验收标准

- 固定输入和随机种子总能得到相同牌局结果。
- 非法动作返回明确错误，且不改变牌局状态和版本号。
- 其他玩家快照不包含本人暗牌数据。
- 四种规则都能从发牌运行到正常结算。
- 核心规则单元测试覆盖率目标不低于85%。
